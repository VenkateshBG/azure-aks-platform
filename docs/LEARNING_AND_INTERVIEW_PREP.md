# Learn it, then be able to defend it

Rule: **you may only put on your resume what you can explain without looking.** Interviewers for DevOps/Cloud roles
open the repo and ask "why did you do it this way?". Spend as much time here as on building.

## Study order (while the first `terraform apply` runs, and on day 4)

| # | Topic | Time | How to learn it *using this repo* |
|---|---|---|---|
| 1 | Helm basics | 1 h | Run `helm template eg oci://docker.io/envoyproxy/gateway-helm --version v1.7.5 \| less` — see the YAML a chart generates. Read `k8s/platform/envoy-gateway-values.yaml`: a values file *overrides* chart defaults. Know: chart, release, values, `helm upgrade --install`, `helm list`, `helm rollback`. |
| 2 | Prometheus + Grafana | 1.5 h | Port-forward Prometheus (9090). Run these queries and understand each: `up`, `rate(http_requests_total[1m])`, `histogram_quantile(0.95, sum by (le)(rate(http_request_duration_seconds_bucket[2m])))`. Know: scrape → TSDB → PromQL → alert rule → (Alertmanager) and counter vs gauge vs histogram. |
| 3 | Gateway API vs Ingress | 45 min | Read `k8s/base/gateway.yaml`. GatewayClass (who implements) → Gateway (listener/LB) → HTTPRoute (routing). Role-oriented: platform team owns Gateway, app team owns routes. |
| 4 | OIDC federation | 45 min | Draw the flow: GitHub issues a short-lived JWT (`sub` = repo+branch/environment) → Entra ID checks it against the federated credential → returns an Azure token. No secret exists. |
| 5 | Terraform state & locking | 30 min | Where is state? (Blob, versioned.) How is it locked? (blob lease.) Why remote? (team + CI.) What if two applies run? (lock + `concurrency:` in the workflow.) |
| 6 | Kubernetes probes/HPA/PDB | 30 min | You know k8s — just map each field in `k8s/base/deployment.yaml` to *why* it is there. |
| 7 | AKS networking | 30 min | Azure CNI **Overlay** (pods get IPs from a private pod CIDR, saves VNet IPs) + **Cilium** dataplane (eBPF, enforces NetworkPolicy). |

## Hands-on drills (each 5 minutes, each makes a great interview story)

1. **Break it on purpose:** `kubectl -n demo-dev set image deploy/aks-platform-api api=nonexistent:1` → watch `maxUnavailable: 0` keep the old pod serving → `kubectl rollout undo`.
2. **Probe failure:** change the readiness probe path to `/nope` in a PR and let the pipeline deploy it → the new pod never becomes Ready, the rollout stalls, and the old pods keep serving traffic (`kubectl -n demo-dev rollout status` shows it waiting). Then revert.
3. **NetworkPolicy proof:** run a pod in another namespace and `wget` the service → blocked; from `demo-dev` → allowed.
4. **Secret rotation:** change `app-api-key` in Key Vault; `rotation` is enabled so the mounted file updates (poll interval ~2 min) without a redeploy.
5. **Drift:** change something in the portal, run the Terraform plan → see the drift detected.
6. **Roll back a bad deploy via Git:** revert the commit; the pipeline redeploys the previous image.

## The "walk me through your project" answer (practice out loud, 2 minutes)

> "I built a production-style Kubernetes platform on Azure, entirely as code. Terraform provisions the network, registry, an AKS cluster, Key Vault and budget alerts, with remote state in a storage account. A GitHub Actions pipeline authenticates to Azure with OIDC, so there are no stored credentials. On every pull request it lints and tests the FastAPI app, scans the image with Trivy, validates the Kubernetes manifests and posts a `terraform plan` to the PR. On merge, it applies infrastructure changes, builds and pushes the image to ACR and deploys with Kustomize overlays. Traffic comes in through the Kubernetes Gateway API using Envoy Gateway — I chose that over Ingress-NGINX because it was retired in March. Secrets live in Key Vault and are mounted into pods with the CSI driver. The app is autoscaled with an HPA and monitored with Prometheus and Grafana, and I load-tested it to show it scaling. The whole thing ran on a 4-vCPU quota, so I sized everything for two small nodes and added budget alerts and a teardown script."

## Interview questions you should now be able to answer

**Terraform**
1. Why a remote backend? What provides locking in Azure? *(Blob lease; versioning for recovery.)*
2. How do you avoid secrets in Terraform/state? *(OIDC auth; secrets generated by Terraform do land in state — so state storage is private, RBAC-protected and encrypted; prefer generating secrets outside TF in real prod.)*
3. `count` vs `for_each`? Where did you use `for_each`? *(Key Vault admin role assignments — stable keys, no index shifting.)*
4. What does `terraform plan` on a PR give you? *(Reviewable change set; drift detection.)*
5. Why modules? *(Reuse, boundaries, versionable interfaces; envs compose them.)*
6. What is the `time_sleep` for? *(Azure RBAC propagation delay — honest workaround.)*

**Azure / AKS**
7. Managed identity vs service principal? *(No credentials to manage; AKS uses kubelet identity for ACR pull.)*
8. How does AKS pull from ACR without a pull secret? *(AcrPull role on the kubelet identity.)*
9. Azure CNI Overlay vs kubenet vs Azure CNI? *(Overlay: pod IPs from overlay CIDR, scalable, still integrates with VNet; kubenet is being retired.)*
10. Why Free control-plane tier and what do you lose? *(No uptime SLA, fewer nodes supported — fine for dev.)*
11. How would you upgrade this cluster? *(Needs surge capacity — raise quota or set max surge to a node; test in a lower environment first.)*
12. Key Vault RBAC vs access policies? *(RBAC is the current model: unified, auditable, scoped; access policies are legacy.)*

**Kubernetes**
13. Liveness vs readiness vs startup probes? *(Restart vs traffic gating vs slow starters.)*
14. Why `requests` and `limits`, and how does HPA use them? *(HPA % is of the **request**; no request = no scaling.)*
15. What does `maxUnavailable: 0` guarantee? *(No capacity drop during rollout.)*
16. What does a PodDisruptionBudget protect against? *(Voluntary disruptions: drains, upgrades.)*
17. NetworkPolicy default-deny — how did you allow Prometheus? *(Namespace selector on `monitoring`.)*
18. Ingress vs Gateway API? *(See topic 3.)*
19. Why `readOnlyRootFilesystem` and non-root? *(Limits blast radius of a compromise.)*

**CI/CD**
20. What is OIDC federation and why is it better than a client secret? *(Short-lived, scoped to repo/branch/environment, nothing to leak or rotate.)*
21. How do you stop two deploys colliding? *(`concurrency` groups; Terraform state lock.)*
22. How would you do a prod deploy safely? *(Environment with required reviewers; same artifact (image tag = commit SHA) promoted, not rebuilt.)*
23. Why tag images with the commit SHA and not only `latest`? *(Traceability, rollbacks, reproducibility.)*
24. Where does security scanning happen? *(Trivy in CI gate on CRITICAL; Dependabot would be a next step.)*

**Monitoring**
25. Pull vs push monitoring? *(Prometheus pulls/scrapes; ServiceMonitor tells it what.)*
26. Why histograms for latency? *(Aggregatable percentiles across pods.)*
27. What would you alert on? *(Symptoms users feel: error rate, latency, availability — not CPU alone.)*

**Judgement ("tell me about a trade-off")**
28. *Ingress-NGINX retired → Gateway API; Microsoft's app-routing Gateway add-on runs istiod with ≥2 replicas, too heavy for 4 GiB nodes → Envoy Gateway with capped resources.* Great story: you researched, found a constraint, chose deliberately.
29. *Alertmanager disabled to save memory; here's how I'd add it.*
30. *No auto-upgrade because surge needs quota; here's the production approach.*

## What NOT to claim

- Don't say "Argo CD", "Helm charts I authored", "service mesh", or "Azure DevOps" unless you actually did it. You *used* Helm to install charts — say exactly that.
- Don't claim production traffic or users. Say "production-style" and "load-tested".
- If asked what you'd improve: TLS + cert-manager, Argo CD (GitOps), Alertmanager routing, private cluster + private endpoints, Azure Policy, multi-environment clusters.
